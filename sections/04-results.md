**Результаты оценки качества генераторов**

Разработанные генераторы задач были реализованы на языке Python. Для получения оценок производительности было автоматически создано по 2000 задач каждым из 2 генераторов, при генерации задач замерялось время работы генераторов. Замеры выполнялись на компьютере со следующими характеристиками: Intel Core i3-1115G4 @ 3.00 GHz, 8 GB RAM, SSD 256 GB PCIe-4, Windows 11, Python 3.12.0.

Производительность генератора задач на работу с СКВ git ниже, чем производительность генератора задач на разрешение зависимостей. Это связано с тем, что при обновлении индекса по @tbl:file-actions производится запись файлов на диск и их чтение с диска, а при выполнении действий из @tbl:git-actions обновляется временный репозиторий git при помощи межпроцессной коммуникации с утилитой командной строки git, которая также сохраняет на диск сведения об изменениях, вносимых в репозиторий.

Известно, что NP-полные задачи вызывают существенные затруднения у LLM [@xu2024]. Поскольку задача разрешения зависимостей является NP-полной [@vouillon2013], ожидается, что задачи, созданные разработанными генераторами задач на работу с git из командной строки и на разрешение зависимостей, также вызовут затруднения у LLM.

Для проверки, смогут ли такие LLM, как ChatGPT-4o mini, DeepSeek, YandexGPT 5 Pro, GigaChat справиться с задачами на работу с git из командной строки, на вход перечисленным LLM были поданы текстовые описания 10 сгенерированных графов коммитов. При генерации графов коммитов использовались следующие параметры генератора задач на git: $B_{\max} = 4$, $F_{\max} = 4$ (см. @fig:gitlog). Кроме графа коммитов на вход LLM подавался следующий текстовый запрос: «Создайте в командной строке git-репозиторий, соответствующий логу, приведенному ниже». Установлено, что ни одна из рассмотренных LLM не справилась с решением задачи на git.

Для проверки, смогут ли LLM справиться с тестовыми задачами разрешения зависимостей, на вход перечисленным LLM были поданы 10 сгенерированных графов зависимостей в формате dot, используемом в graphviz [@ellson2004]. При генерации графов использовались следующие значения параметров алгоритма, показанного на @fig:dag: $d_{\min} = 4$, $d_{\max} = 5$, $w_{\min} = 2$, $w_{\max} = 3$, $k_{\min} = 1$, $k_{\max} = 2$. Вследствие этого были сгенерированы графы зависимостей небольшого размера, подобные графу, показанному на @fig:deps – такие задачи могут быть легко решены вручную. Кроме графа зависимостей на вход LLM подавался следующий текстовый запрос: «Решите задачу разрешения зависимостей для рисунка, приведённого ниже. Необходимо найти минимальное по числу пакетов решение. Задача разрешения зависимостей считается решённой только в том случае, если правильно указаны версии для каждого из перечисленных ниже пакетов». На основе полученных ответов было подсчитано число правильно решённых задач, а также число правильно выбранных версий пакетов.

Результаты приведены на @fig:llm.

![Количество: а) правильно решённых LLM задач; б) правильно выбранных LLM версий пакетов](./images/fig7.png){#fig:llm width=6.0in}

Как показано на @fig:llm (а), больше всего задач разрешения зависимостей было правильно решено LLM ChatGPT-4o mini – правильные версии всех пакетов, показанных в графе зависимостей, были указаны LLM для 3 из 10 сгенерированных задач. LLM DeepSeek и YandexGPT были решены 2 задачи, LLM GigaChat была решена 1 задача. Общее число правильно выбранных версий пакетов оказалось наибольшим у ChatGPT-4o mini (21 из 34), но, несмотря на число правильно выбранных версий пакетов, число задач, решённых без ошибок, оказалось небольшим.

Полученные в результате эксперимента оценки качества генераторов задач показывают, что сгенерированные задачи вызывают существенные затруднения у LLM. Вследствие этого использование разработанных генераторов задач позволяет обеспечить объективный контроль навыков и знаний студентов на промежуточной и итоговой аттестациях, а также мотивирует студентов вырабатывать компетенции, необходимые как на рынке труда, так и для сдачи зачёта.

На основе полученных оценок для объективного контроля знаний во время проведения контрольно-измерительных мероприятий по дисциплине «Конфигурационное управление» в РТУ МИРЭА студентам предлагалось решить, на выбор, 1 задачу на работу с git из командной строки или 3 задачи на разрешение зависимостей, при этом задача на разрешение зависимостей считалась решённой только в том случае, если были правильно указаны версии для каждого из пакетов в графе зависимостей. Проверка решений задач на разрешение зависимостей выполнялась автоматически, проверка задач на работу с git из командной строки выполнялась преподавателем вручную. Студенты, не справившиеся с 3 задачами на разрешение зависимостей, имели возможность за оставшееся время решить задачу на работу с git из командной строки. Студенты, не справившиеся с задачей на работу с git, имели возможность за оставшееся время решить 3 задачи на разрешение зависимостей.

В частности, на @fig:exam а) приведено число полученных студентами оценок за сдачу теста с автоматически сгенерированными задачами на разрешение зависимостей, а на @fig:exam б) приведено распределение времени, затраченного на попытку сдачи этого теста.
